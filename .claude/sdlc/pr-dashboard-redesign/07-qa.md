## 1. Golden path
- Sign-in → PR list renders as single-column shadcn/ui `Card`s, full width,
  with avatar, title, `#number opened by author on date`, and a `Badge` for
  status (Merged = purple, Closed = red) — confirmed by eye. ✅
- Filter tabs (`All`/`Open`/`Merged`/`Closed`), built on shadcn/ui `Tabs`,
  switch the list correctly; `Open` on the current repo state correctly
  shows "No pull requests match this filter." (no open PRs exist right now)
  — confirmed this is real empty-repo state, not a bug, by cross-checking
  `All`/`Closed`/`Merged` show the same 12 historical PRs. ✅
- Summarize: clicked on PR #13 (merged) → real Gemini-backed summary
  rendered inline, button disappears after success (single-use per row, as
  designed) — confirmed the redesign didn't regress the mock/cache/loading
  behavior underneath. ✅
- Show comments: click → visible `Skeleton` loading state → resolves to the
  real existing comment list (2 comments, correct author/date/body) plus a
  `Leave a comment…` `Textarea` + `Comment` button. Not submitted (see scope
  note). ✅
- Request changes: click → reveals a `Textarea` (`What needs to change?`) +
  `Submit` button inline, same toggle pattern as Show comments. Not
  submitted (see scope note). ✅
- Merge: no open/unmerged PR currently exists to render `MergeAction`
  against — confirmed the component correctly does **not** render for
  Merged/Closed PRs (matches the "only for open unmerged PRs" rule), but the
  merge-confirm dropdown/Confirm/Cancel flow itself wasn't re-exercised this
  session.

## 2. Edge cases
- Empty filter state (`Open`, zero results): renders a plain, legible "No
  pull requests match this filter." message, no layout break. ✅
- Loading state (comments fetch): `Skeleton` placeholder shown correctly
  before resolving — confirmed via screenshot mid-fetch. ✅
- Summarize error state: not re-triggered this session (no forced-failure
  path available without breaking a working call on purpose); trusted from
  the token-fix verification above, which did exercise both the error path
  (pre-fix, real 401 + Retry link rendered and worked) and the success path
  (post-fix).

## 3. Regressions
- Checked neighboring actions on the same card don't interfere with each
  other: opening Show comments then Request changes on the same card (PR
  #13) rendered both panels correctly stacked, no state bleed between them. ✅
- Checked a different row (PR #10, Merged) independently still shows its own
  Summarize/Request changes/Show comments toolbar, unaffected by PR #13's
  expanded panels — per-row state isolation (React per-instance state, see
  AGENTS.md) still holds after the redesign. ✅
- Browser console: no application errors on load or after interactions (two
  `MaxListenersExceededWarning` messages present, but sourced from a Chrome
  extension's content script, not app code — confirmed by the
  `chrome-extension://` origin in the console output). ✅

## 4. Responsive / accessibility basics
- Resized to 390×844 (mobile): single-column card layout holds, no
  horizontal overflow, long PR titles truncate with ellipsis, filter tabs
  and action toolbar wrap/stack without breaking, comment list and textarea
  remain usable. ✅
- Keyboard navigation: `Tab` moves focus through interactive elements
  (filter tabs, textarea, submit button, comment author link) in a sane
  order; a visible focus ring (white outline) renders on the focused
  element — confirmed by screenshot mid-tab-sequence. ✅
- Dark mode: renders dark by default with no toggle UI, matching the
  OS-preference-only decision in `02-grilled-requirements.md` (system Chrome
  profile is dark-themed). Light-mode rendering and the dark-mode-variant
  bug noted as fixed in `05-review.md` were not independently re-verified
  this session.
